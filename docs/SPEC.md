# Focus extension: build spec (source of truth)

Name: **WeDeepFocus** (lives in `i18n/common.json` keys `appName` / `appShortName`). Every agent must code against this spec exactly. If something is ambiguous, pick the simplest option consistent with the spec and note it in your final report.

## 1. Product summary

A public Chrome extension (Manifest V3, Chrome Web Store) that blocks distracting sites during focus time and shows the user's own goals instead.

- The user chooses sites: preset categories (social, video, messaging, news, shopping) with per-site opt-out, custom domains, and one click "Block this site" from the popup.
- A block is active during recurring weekly time slots (e.g. Mon to Fri 07:00 to 14:00, overnight allowed like 22:00 to 02:00) or during a manual session started from the popup (10, 20, 30 min or custom 1 to 480 min). Live countdown in the popup, remaining time in the toolbar badge.
- Blocked navigations are redirected to `blocked/blocked.html`: goals, a motivational line, remaining time, a "Back to work" button, and a friction flow (2 questions, then typing a long sentence with paste disabled and typos rejected) that grants a **10 minute pass for that site only**.
- Strict mode: no stop button. During an active block, settings can only get stricter: add sites, enable categories, re-include excluded sites, add schedules, extend a session. Removing, disabling, shortening or editing existing schedules is refused.
- Free, with a "Buy me a coffee" Stripe link in the popup footer, options and onboarding done screen. Never on the blocked page.
- Zero backend, zero data collection. Settings in `chrome.storage.sync`, runtime state in `chrome.storage.local` / `chrome.storage.session`.
- Languages: English (default) and French, via `chrome.i18n` (`_locales`). French uses "tu", warm and direct. English is casual "you".

## 2. Global rules for every agent

1. **Never use the em dash (U+2014) or en dash (U+2013)** anywhere: UI copy, messages, comments, docs, commit messages. Use commas, colons, parentheses, "to"/"à" for ranges ("07:00 to 14:00", "07:00 à 14:00"), or a plain hyphen in code.
2. Vanilla JS, ES modules (`<script type="module">`, `"type": "module"` service worker). No framework, no bundler, no npm runtime dependency, no remote code, no remote fonts, no CDN. Everything is bundled in `extension/`.
3. Never inject user-controlled strings (domains, goals, URLs) with `innerHTML`. Use `textContent` / DOM APIs. Static templates with `innerHTML` are fine only if they contain no user data and no i18n strings (i18n strings go through `textContent`).
4. All user-visible strings come from `chrome.i18n.getMessage` (via `shared/i18n.js`). No hard-coded UI text in JS or HTML (HTML may contain an English fallback inside elements that have `data-i18n`, it gets replaced).
5. Pure modules (listed in section 5) must not reference `chrome` or `document` so they can be unit tested with `node:test`.
6. Use the design tokens and components from `extension/ui/common.css` (already written, do not edit it; add page-specific CSS in your own page CSS file). Light and dark mode must both work (use the CSS variables).
7. Accessibility: real `<button>`/`<label>`, visible focus, `aria-live` on countdowns/errors where useful, respects `prefers-reduced-motion`.
8. Match the code style: small functions, descriptive names, sparse comments (only for non-obvious logic).
9. Add `data-testid` attributes exactly as listed in this spec (e2e tests rely on them).
10. Do not edit files owned by another agent (section 3). If you need something from another module that is not in the spec, implement a local helper in your own files and mention it in your report.

## 4. Data model

### chrome.storage.sync (settings, synced across the user's Chrome profiles)

Stored as four keys (each must stay under 8 KB):

```js
sites: {
  categories: { social: true, video: false, messaging: false, news: false, shopping: false },
  excluded: [],   // preset domains the user unchecked, normalized, e.g. ["linkedin.com"]
  custom: []      // user-added domains, normalized, max MAX_CUSTOM_DOMAINS
}
schedules: [
  { id: "s_k3j2", days: [1, 2, 3, 4, 5], start: "07:00", end: "14:00", enabled: true }
  // days use Date#getDay numbering: 0 = Sunday ... 6 = Saturday. UI always displays Monday first.
  // start/end "HH:MM" 24h local time. end < start means the slot crosses midnight and belongs to the start day.
  // start === end is invalid (UI must prevent it).
]
goals: { items: ["", "", ""], showQuote: true }   // exactly 3 strings, each max GOAL_MAX_LENGTH chars
prefs: { onboarded: false }
```

Defaults (in `shared/constants.js` as `DEFAULT_SETTINGS`): social enabled, no schedule, empty goals, showQuote true, onboarded false.

### chrome.storage.local (runtime state, this device only)

```js
session: { startedAt: 1727420000000, endsAt: 1727421200000 } | null   // manual session
passes:  { "linkedin.com": 1727420600000 }                           // domain -> expiresAt ms
stats:   { day: "2026-09-27", blocked: 3, resisted: 2 }              // local counters shown to the user only
```

### chrome.storage.session (in-memory, owned by background)

`enforced: string[]` domains currently redirected (used to detect newly enforced domains and redirect their already open tabs).

## 6. Background service worker (background agent)

All listeners registered synchronously at top level. Stateless: every event calls `reconcile()`; reconciles are serialized through a promise chain.

`reconcile()` steps:
1. Read settings + runtime, `now = Date.now()`. Drop expired passes (write back if changed).
2. `state = blockState(now, { schedules, session })`.
3. `domains = effectiveDomains(settings.sites, uiLocale)`; `granted = domainsForOrigins((await chrome.permissions.getAll()).origins, domains)`; `missing = domains - granted`.
4. `enforced = state.active ? granted.filter(d => !(passes[d] > now)) : []`.
5. `chrome.declarativeNetRequest.updateDynamicRules({ removeRuleIds: existing ids, addRules: buildRules(enforced, chrome.runtime.getURL("blocked/blocked.html")) })`.
6. Newly enforced domains (not in `storage.session.enforced`): query open tabs `chrome.tabs.query({ url: originPatterns(newDomains) })` and `chrome.tabs.update(tab.id, { url: blockedUrl + "#" + tab.url })`. Save `enforced`.
7. Badge: active -> `setBadgeText(formatBadge(state.until - now))`, accent background `#1f6f5c`, white text; inactive -> "". Tooltip title: `t("badge_title_active", [formatClock(until)])` or appName.
8. Alarms: `transition` at `nextTransition(...)` (clear if null; if the time is under 30 s away, still set it, Chrome clamps); `tick` every 1 minute only while active (clear otherwise).

Events: `runtime.onInstalled` (reason "install" -> write DEFAULT_SETTINGS for missing keys, open `onboarding/onboarding.html`; always reconcile), `runtime.onStartup`, `alarms.onAlarm`, `storage.onChanged` (sync or local, ignore `stats`-only changes), `permissions.onAdded/onRemoved`, `runtime.onMessage`.

Messages (`{ type, ...payload }` -> response):
- `getState` -> `{ ok: true, now, block: state, session, passes, domains, granted, missing, settings, stats, locale }`
- `startSession { minutes }` -> validate integer 1..480 (else `{ ok: false, reason: "invalid_minutes" }`). `endsAt = max(existing active session endsAt, now + minutes*60000)`, `startedAt` = existing active session startedAt or now. Reconcile. Return getState.
- `extendSession { minutes }` -> base = `max(session active ? session.endsAt : 0, block.active ? block.until : now)`; `session = { startedAt: session?.startedAt ?? now, endsAt: base + minutes*60000 }`. Reconcile. Return getState.
- `grantPass { domain }` -> ok only if block active and domain is currently enforced; `passes[domain] = now + PASS_MINUTES*60000`; reconcile; `{ ok: true, expiresAt }` else `{ ok: false, reason: "not_blocked" }`.
- `saveSettings { patch }` -> current `state.active`; `checkChange(prev, merged, state.active)`; refuse with `{ ok: false, reason }`; validate (custom domains normalized, deduped, max 200; schedules valid; goals 3 strings trimmed to 140); write `chrome.storage.sync.set(patch)`; `{ ok: true }`.
- `recordStat { kind }` -> increments today's counter in `stats` (reset when `day` changes).
- `openOptions` -> `chrome.runtime.openOptionsPage()`. `openOnboarding` -> open onboarding tab.

Test hook: `globalThis.__focus = { reconcile }` (harmless in production).

### 7.4 Blocked page (blocked agent)

## 11. Amendments v2 (hardening after research, supersede earlier sections where they conflict)

### 11.1 Permissions and rules
- Manifest permissions become `["declarativeNetRequest", "storage", "alarms", "activeTab"]` (NOT `declarativeNetRequestWithHostAccess`). Reason (verified in Chromium source): with `declarativeNetRequest`, `block` and `allow` rules work on every host without host permission, only `redirect` needs host access, and a redirect without host access is silently dropped with no fallback. So we generate two rules. Install warning becomes "Block content on any page", which is honest for a blocker.
- `minimum_chrome_version` "121". `web_accessible_resources` gets a second entry `{ "resources": ["blocked/blocked.html"], "extension_ids": ["*"] }` (navigations started by other extensions, e.g. new tab page extensions).
- `rules.js`: `buildRules({ redirect, block }, blockedPageUrl)`:
  - rule id 1 (only if `redirect.length`): redirect, same shape as before, `requestDomains: redirect`.
  - rule id 2 (only if `block.length`): `{ id: 2, priority: 1, action: { type: "block" }, condition: { requestDomains: block, resourceTypes: ["main_frame"] } }`.
  - Keep `BLOCK_RULE_ID = 1`, add `FALLBACK_RULE_ID = 2`. Callers always `removeRuleIds: [1, 2]` (plus any existing ids) in the same `updateDynamicRules` call.
- Background reconcile: `enforced = active ? effective minus live passes : []`; `redirect = enforced ∩ granted`, `block = enforced minus granted`. Sites without permission ARE blocked (Chrome's error page) and granting access upgrades them to the goals page. Update UI copy of the missing-permission banners accordingly: "These sites are blocked with Chrome's error page. Allow access to show your goals page instead." (popup, options, onboarding done screen).
- Every domain passed to rules must be re-validated with `normalizeDomain` (drop invalid ones and log) because one invalid entry makes the whole `updateDynamicRules` call reject. Catch and log the rejection.
- `await` `updateDynamicRules` before sweeping tabs and before responding to `grantPass` / `startSession` / `extendSession` (the page navigates right after the response).
- Safety net for SPA navigations, back/forward cache and service-worker-served pages: register at top level `chrome.tabs.onUpdated.addListener((tabId, changeInfo, tab) => ...)`: if `changeInfo.url` is http(s) (only visible for hosts we have permission for), a block is active, the host matches a domain in the current `redirect` list and has no live pass, `chrome.tabs.update(tabId, { url: blockedUrl + "#" + changeInfo.url })`. Read the current redirect list from `chrome.storage.session` (key `enforced`, written by reconcile) so the handler is cheap and survives worker restarts.

### 11.2 Robustness
- Do NOT write defaults into `chrome.storage.sync` on install (on a second device, sync data may not have arrived yet and writing defaults would overwrite the user's synced settings). Defaults are merged at read time only (`getSettings`).
- Strict snapshot (enforced in the worker, not just the UI): in `chrome.storage.local` key `strict: { domains: string[], until: number } | null`. While a block is active, reconcile writes/updates it with `domains = union(previous snapshot domains, current effective)` and `until = max(previous until, state.until)`. While `now < strict.until`, the block stays active even if schedules were removed or shortened through sync from another device or DevTools, and effective domains are the union. Clear it once `now >= until` and no block is active. Put this logic in a pure function (e.g. in `background/logic.js`) and unit test it.
- Alarms: use ONE alarm named `reconcile` re-armed at the end of every reconcile: `when = max(now + 1000, min(nextTransition, nextBadgeChange, now + 5 min))`, `periodInMinutes: 5` as a heartbeat. `nextBadgeChange` is the instant the badge text changes (`until - (ceilMinutes - 1) * 60000`). Clear legacy alarm names (`transition`, `tick`) on startup. Reason: separate alarms delay each other because Chrome rate-limits alarm polling per extension.
- Also call reconcile from top-level worker code (re-enabling the extension fires neither onStartup nor onInstalled).
- Keep the storage.onChanged loop guard: ignore changes that only touch `stats` or keys written by reconcile when their value didn't change.

### 13.8 Payment verification with Stripe (supersedes the honor system in 13.1 to 13.3)
Owner decision: the payment must be really verified. No webhook/database needed: a tiny server creates a Stripe Checkout Session for the exact amount and later asks Stripe whether that session is paid.
- Server (Vercel serverless functions in `landing/api/`, deployed with the landing, no npm dependency, Stripe REST API via fetch, env `STRIPE_SECRET_KEY` set by the owner in Vercel, env `SITE_URL`):
  - `POST /api/checkout` JSON `{ amount, token, locale }` (amount integer 1..500, token 32 to 64 hex chars, locale "en"|"fr") -> creates a Checkout Session: mode payment, one line item with `price_data` (currency eur, unit_amount amount*100, product name "WeDeepFocus: session ended early" / "WeDeepFocus : session arrêtée avant la fin"), `client_reference_id = token`, `metadata[token] = token`, `success_url = SITE_URL + "/paid/?session_id={CHECKOUT_SESSION_ID}"` (FR: `/fr/paid/...`), `cancel_url = SITE_URL + "/paid/?canceled=1"`, `locale` en/fr. Responds `{ url, sessionId }`. Invalid input -> 400 `{ error }`.
  - `GET /api/verify?session_id=...&token=...` -> retrieves the session from Stripe and answers only `{ paid: boolean }` (`paid` = `payment_status === "paid"` and `client_reference_id === token`). Never echoes other session data.
  - Both: CORS `Access-Control-Allow-Origin: *`, `OPTIONS` preflight, `Cache-Control: no-store`, no cookies, no logging of tokens.
  - Static pages `/paid/` and `/fr/paid/` (built by landing/build.mjs): "Payment received. Go back to your tab: your session is ending." / canceled variant.
- Extension:
  - constants: `PAYMENT_API` (base URL of the deployment, placeholder `https://PLACEHOLDER.example` until the domain exists). Remove `PAYMENT_LINKS` and `CONFIRM_DELAY_SECONDS`.
  - `shared/payment.js`: keep `isPresetAmount`, `isValidAmount`, `formatAmount`; add `newPaymentToken()` (crypto 32 hex), `createCheckout({ amount, token, locale })` -> `{ ok: true, url, sessionId }` or `{ ok: false, reason: "payment_unavailable" }`, `verifyPayment({ sessionId, token })` -> `{ ok: true, paid }` or `{ ok: false, reason: "payment_unavailable" }` (fetch with a 10 s timeout, never throws).
  - Background `endSession({ method: "paid", sessionId, token })` calls `verifyPayment` itself and refuses with `payment_not_verified` unless paid; `endSession({ method: "sentence" })` unchanged.
  - Blocked page: pay -> `createCheckout` -> open `url` with `chrome.tabs.create` -> `friction-step-waiting` ("Waiting for your payment", spinner, `friction-reopen` "Open the payment page again", `friction-confirm-back` back) polling `verifyPayment` every 3 s for up to 30 min -> paid -> `api.endSession({ method: "paid", sessionId, token })` -> `friction-ended`. Errors show `friction-pay-error` with retry; "Skip for free" always stays available. No "I've paid" honor button.
  - No new manifest permission (the server allows CORS).
- Privacy/store: the extension contacts the payment server only when the user clicks Pay; it sends the amount, the language and a random one-time code, and receives the Stripe page URL and paid/not paid. No personal data; Stripe handles the payment. Declare in-app purchases on the store.
- Tests: e2e mock `/api/checkout` and `/api/verify` on the local fixture server by patching `PAYMENT_API` in the temp copy of the extension.
